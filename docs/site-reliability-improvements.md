# 学習サイトの信頼性改善

実装・検証日: 2026-09-05。対象は外部評価で提案した8項目。既存の学会データ、`.agents/`、`lecture-factory/` の作業差分は保持。

## 実装した仕様

| 項目 | 実装・完了条件 |
| --- | --- |
| ① 進捗の取り込み | schemaVersion・構造・日時・数値範囲を検証。不正なJSONでは既存状態を変更しない。取り込み件数を表示し、再確認後に直前データをバックアップして置換。バックアップから復元可能。壊れた保存データの明示的な置換でも元の文字列を保護する。 |
| ② 複数タブ | Web Locks の同一ロック内で最新保存状態を読み、更新関数を適用。別教材の同時更新、リセット・取り込みと古いタブの更新を検証。storageイベントで表示同期。バッジ判定も更新時の最新状態で行う。 |
| ③ 問い合わせ | 4,000文字の本文を切り詰めず配送。Discordのdescription 4,096文字・embed合計6,000文字以内。JSONの構文・型不正は400。外部通信に10秒のタイムアウト。 |
| ④ 公開前検証 | `npm run build` のprebuildでコンテンツ検査と回帰テストを必須化。`npm run verify` でさらに本番ビルドを使ったPC・スマホ幅の操作テスト。GitHub ActionsをPR、main/masterへのpush、手動実行に設定。 |
| ⑤ 保存失敗 | 全ページに警告と現在の進捗のダウンロードを表示。未保存状態を古い保存状態で上書きしない。排他制御が使えない環境でも競合する永続書き込みは行わず、画面内で保持して書き出しを案内。 |
| ⑥ 読み込み障害 | 正常な空配列と、ファイル・形式の異常を区別。異常はサーバーログに記録してエラー境界へ伝える。失敗したキャッシュを破棄し、復旧後の再試行を可能にする。 |
| ⑦ 検索URL | `q` / `theme` / `asset` / `year` をURLに保存。再読み込み・戻る・進むで復元。無関係なクエリやハッシュは維持。検索入力は履歴を置換し、選択・リセットは履歴に追加。 |
| ⑧ フォント | 既存Inter/Noto Sans JPのWOFF2とライセンスを同梱。Unicodeの範囲ごとの読み込みを維持。ビルド時・閲覧時のGoogle Fonts接続は不要。 |

## 運用

Node.js 22、Python 3、npmを使用する。

```sh
npm ci
npx playwright install chromium
npm run verify
```

- `npm test`: 進捗、問い合わせ、教材読み込み、検索条件の回帰テスト。
- `npm run check:content`: 既存の公開情報検査と教材生成のdry-run。
- `npm run build`: 上記検査と回帰テストを通過した場合だけ本番ビルド。
- `npm run test:e2e`: ビルド済みアプリを127.0.0.1:4317に起動して操作検証。既存サーバーを流用しない。
- `npm run verify`: ビルドと操作検証を順に実行する公開前の入口。
- CI失敗時はGitHub Actionsの `browser-test-results` からトレースを確認する。
- 学習記録は引き続き端末内保存。取り込み・リセットのバックアップは直前1回分。未保存警告が出たら、ダウンロードしてから再読み込みする。
- 読み込み障害の管理者向け記録は `[site-data]` のサーバーログ。外部通知は追加していない。
