# 学会カレンダー 挙動仕様書（旧実装解析 → React再実装用）

対象ページ: `/annual-meetings-2026`（2026年度 学会年会一覧）

この文書は、以下の旧実装ファイルを読んだ上で、実装者がそれらを読み返さずに React で再実装できる粒度まで「挙動」を書き下したものである。見た目のCSS値そのものではなく、「どんな状態のときに何が表示/非表示になるか」を規則として記録する。

参照した実装ファイル:

- `public/assets/annual-meetings-2026.js`（描画ロジック本体。今日ハイライト・当月初期スクロール・全月表示を含む最新版、コミット `d034378`）
- `public/annual-meetings-2026.html`（旧静的ページのDOM構造）
- `app/annual-meetings-2026/page.tsx`（現行Next.jsラッパー）
- `public/data/annual-meetings-2026.js`（データ本体）
- `public/assets/styles.css` の `.calendar-*` / `.meeting-*` 系ルール
- `app/site-data.ts`（SSRでのデータ読み込みとTS型定義。実データより型が不完全であることが判明したため8章に記載）

## 1. データスキーマ

### 1.1 トップレベル（`window.ANNUAL_MEETINGS_2026_DATA`）

| フィールド | 型 | 意味 |
|---|---|---|
| `fiscalYear` | string | 表示用の年度ラベル（例: `"2026年度"`） |
| `period.start` | `YYYY-MM-DD` | カレンダービューが描画する年度の開始日（現行値 `2026-04-01`） |
| `period.end` | `YYYY-MM-DD` | 年度の終了日（現行値 `2027-03-31`） |
| `verifiedAt` | `YYYY-MM-DD` | データ全体の最終確認日。ページ上部の「確認日」表示に使う |
| `meetings` | 配列 | 学会イベントのリスト（後述） |

`period` はカレンダービューの月グリッド範囲を決めるためだけに使われる。**リストビューはこの範囲でフィルタしない**（4.1章参照）。

### 1.2 `meetings[]` の各フィールド

| フィールド | 型/必須 | 意味・使われ方 |
|---|---|---|
| `id` | string 必須 | 一意キー。DOM要素のkeyや、カレンダー上の色決定のハッシュ元にも使う |
| `primaryUrl` | string 任意 | 公式サイトURL。カード見出しリンク・画像リンク・カレンダー帯のリンク先の第一候補 |
| `imageUrl` | string 任意 | カード用サムネイル画像URL。空文字/未設定/読み込みエラー時はフォールバック表示（7章） |
| `imageFit` | `"cover" \| "contain"` 任意 | 画像のobject-fit。`"contain"`以外（未設定含む）は`cover`相当の扱い |
| `scope` | `"local" \| "national"` 任意 | `"local"`のときだけカードに固定文言「北海道/札幌」チップを付与（**地域名は`city`から動的生成せずハードコード**、8章の要注意点） |
| `displayMonth` | number（1-12）任意 | 年度内の「何月枠か」を示す整理用の月番号。`startDate`/`sortDate`が両方とも無い（=開催日未確定）場合のみ、並び替え・グルーピングのフォールバックとして使われる。`startDate`があるレコードでは実質参照されない冗長フィールド |
| `status` | `"confirmed" \| "past" \| "pending"` 任意 | 開催状況。実データ上は`confirmed`と`past`のみが使われているが、コードは`pending`（未公表）も想定して分岐を持つ |
| `society` | string 必須 | 学会名（略称）。カレンダー帯のラベルやフォールバック画像の代替テキストに使用 |
| `eventName` | string 必須 | 大会の正式名称。カードタイトル・カレンダー帯のtitle属性に使用 |
| `startDate` / `endDate` | `YYYY-MM-DD` 任意 | 開催期間。**片方だけ設定された状態は「未対応」**（7章）。両方とも無い場合は「会期未公表」表示 |
| `city` | string 任意 | 開催都市。カード上で`venue`の補足として `venue / city` の形で表示。単独では使われない |
| `venue` | string 任意 | 会場名。無ければ「会場未公表」と表示 |
| `theme` | string 任意 | 大会テーマ。空文字/未設定ならカードにその行自体を出さない |
| `leadLabel` / `lead` | string 任意 | 会長・年会長などの肩書きと氏名。**データには存在するが、現行の描画コードはどこにも参照していない（未描画の生きた死にフィールド）**。8章参照 |
| `note` | string 任意 | 学会単位の補足テキスト。カード下部に段落として表示。空/未設定なら非表示 |
| `sources` | `Array<{label, url}>` 任意 | 参照リンク一覧。**実際にはリストとして描画されない**。`primaryUrl`が空のときの代替リンク先として`sources[0].url`だけが使われ、2件目以降は現状どこにも表示されない（4.4章・8章） |
| `archivedAt` | `YYYY-MM-DD` 任意 | データ確定/アーカイブ日の記録用フィールド。**描画コードからは一切参照されない**（社内記録用メタデータ） |
| `sortDate` | `YYYY-MM-DD` 任意・現行データ未使用 | 並び替え専用の日付を`startDate`と別に持たせるための予約フィールド。コードは`sortDate || startDate || (displayMonthからのフォールバック)`の順で参照するが、現行の`public/data/annual-meetings-2026.js`には一件も存在しない |
| `milestones` | 配列 任意 | 演題募集・参加登録などのマイルストーン一覧（1.3章） |

### 1.3 `milestones[]` の各フィールド

| フィールド | 型/必須 | 意味 |
|---|---|---|
| `id` | string 必須 | 一意キー |
| `label` | string 任意 | 表示ラベル（例: `"演題募集"`, `"事前参加登録"`, `"早期参加登録"`）。未設定時は`category`から`"registration"→"参加登録"`、それ以外は一律`"演題募集"`にフォールバックする（`abstract`以外の`category`、例えば将来`"deadline"`を未ラベルで使うと誤って「演題募集」と表示される潜在バグ、8章） |
| `category` | `"abstract" \| "registration" \| "deadline" \| その他/未設定` | 現行データでは`abstract`と`registration`のみ使用。コードは`deadline`用の見た目も用意しているが未使用、それ以外の値・未設定は`"info"`扱い |
| `startDate` / `endDate` | `YYYY-MM-DD` 任意 | 募集/登録期間。片方だけの場合の挙動は7章 |
| `note` | string 任意 | 補足テキスト。カレンダー帯のtitle属性とリストビューの近傍文脈に使われるが、**リストビューのマイルストーン行そのものには表示されない**（カード上は日付のみ） |

補足: ラベル文字列が厳密に`"早期参加登録"`と一致するマイルストーンは、カレンダービューと募集期間サマリーからは**意図的に除外**される（`isVisibleMilestone`）。ただしリストビューのカード内マイルストーン一覧には除外されず表示される。ラベル文字列の完全一致に依存した特別扱いであり、ラベル表記のゆらぎに弱い（8章）。

## 2. ページ構成

### 2.1 タブなし固定表示（タブより上の常設要素）

以下は「カレンダー」「学会一覧」どちらのタブがアクティブでも常に表示される（タブの外側に配置されている）:

1. ページヘッダー（年度ラベル、タイトル、リード文）
2. 「確認日」ノーティス（`verifiedAt`を日本語形式で表示）
3. 「未公表」ノーティス — `status === "pending"`の学会が1件以上あるときだけ表示。**複数件あっても最初の1件の`note`しか表示されない**（`renderPendingNote`が`pendingItems[0].note`のみ参照。7章）。0件なら要素ごと非表示。

### 2.2 タブ切り替え

- タブは2つ: `calendar`（学会カレンダー）/ `list`（学会一覧、デフォルトでアクティブ）。
- `role="tablist"` / `role="tab"` / `role="tabpanel"` のARIAロールを持つ横並びボタン。
- クリックでアクティブタブを切り替え。非アクティブなタブパネルは`hidden`属性で非表示（DOM自体は残る＝再訪時に再描画不要）。
- キーボード操作: フォーカス中のタブボタンで矢印キー左右を押すと、隣のタブへ**フォーカス移動と同時にアクティブ化**（前後のタブへ巡回、末尾の次は先頭へ戻る）。
- アクティブタブの見た目切替とは別に、非アクティブボタンは`tabIndex=-1`にしてTab移動から除外する（ロービングタブインデックス方式）。

### 2.3 カレンダータブ内の要素（上から順）

1. パネル見出し（「学会カレンダー」）と説明文
2. 凡例（`calendar-legend`）— **JSXに静的に埋め込まれた固定2チップ**: 「開催」（`is-event`）と「演題募集」（`is-abstract`）。「参加登録」（`is-registration`）チップは凡例に存在しない（5.4章で詳述する不整合）
3. 募集期間サマリー（`meeting-window-summary`）— 全学会（カレンダーの表示中の月に限らない）の可視マイルストーンを1行ずつ列挙するテキストブロック。該当なしなら固定の案内文
4. カレンダー本体（`meeting-calendar`）— 3章で詳述

### 2.4 学会一覧タブ内の要素

1. ステータスパネル（`meeting-status-panel`）— 読み込み中/エラー時のみ表示（4章・8章）
2. 月別・グループ別セクションの縦積み（4章で詳述）

トグルやフィルタ（絞り込みUI）は現行実装には**一切存在しない**。タブ切り替えとカレンダーの月送りのみが唯一のユーザー操作。

## 3. カレンダービューの挙動

### 3.1 対象期間と月の列挙

- `period.start`〜`period.end`の月初め同士を1か月ずつ辿り、月キー（`YYYY-MM`）の配列を作る（例: FY2026なら `2026-04` 〜 `2027-03` の12件、必ず年度の全月を含む）。
- **その月に開催中のイベントやマイルストーンが1件も無くても、その月はグリッドに含まれる**（＝「全月表示」。以前のバージョンでは該当イベントがある月だけに絞り込んでいたが、現行版で撤廃された。8章）。

### 3.2 1か月分のグリッド構成

- 週の開始曜日は**日曜**（`日 月 火 水 木 金 土`の7列）。
- グリッドは常に**6行×7列＝42マス**固定。月初日の曜日に応じて、前月末の日付が先頭マスに繰り上がる（例: 1日が水曜なら日〜火のマスは前月末日を表示）。同様に月末超過分は翌月初日で埋まる。
- 当月に属さない繰り上げ/繰り越しマスには`is-outside`（減光表現）を付与。

### 3.3 月送りナビゲーション（実態は「1か月ずつの単一月表示」）

- 内部的には複数月ページング用の仕組み（`MEETING_CALENDAR_PAGE_SIZE`）を持つが、**現行値は1**。つまり実際の挙動は「常にちょうど1か月だけを表示し、『← 前の月』『次の月 →』ボタンで前後に1か月ずつ移動する」というシンプルなものである。
- 先頭月（年度開始月）では「← 前の月」を無効化、末尾月（年度終了月）では「次の月 →」を無効化。
- ナビゲーションは各月カードの内部・曜日見出し行より上に埋め込まれる（月タイトルは独立した見出し要素ではなく、ナビ中央の「現在表示中の月ラベル」テキストとして表示される）。
- 一度ユーザーが手動で月を移動すると、その位置は保持される（後述3.4の自動選択はページ初回描画時のみ働く）。

### 3.4 初期表示月の決定規則（`initialCalendarIndex`）

1. 「今日（Asia/Tokyo基準）」の年月が年度内の月キー一覧に含まれていれば、その月を初期表示にする。
2. 含まれていない場合（今日が年度範囲外＝年度開始前や終了後）は、年度内で「今日より後」の最初の月を初期表示にする。
3. それも無ければ（今日が年度範囲より後）、年度内の最後の月を初期表示にする。
4. この自動選択はページ初回描画時に一度だけ行われ、以降のカレンダー再描画（月送り操作など）では上書きされない。

### 3.5 「今日」セルの表現

- 表示中の月に「今日」の日付が含まれる場合、そのマスに`is-today`クラスを付与し、`aria-current="date"`と`aria-label="{月}月{日}日 今日"`を設定する。
- 見た目としては、日付数字を丸背景付きの強調表示にする（意味的には「本日マーカー」）。
- 「今日」判定は日本時間基準の日付文字列同士の完全一致で行う。

### 3.6 イベント帯・マイルストーン帯の描画規則

各学会につき、**表示中の月ごとに最大1本の帯**を描画する。優先順位は以下の通り:

1. **開催期間がその月と重なっていれば「開催」帯を描画し、その学会については以降のマイルストーン判定を行わない。** ＝ある月で開催期間とマイルストーン期間が両方その月にかかっていても、マイルストーン帯は表示されない（開催が優先、7章の重要な制約）。
2. 開催期間がその月と重ならない場合のみ、可視マイルストーン（「早期参加登録」ラベルを除く）の中から**その月と重なる最初の1件**を探して帯にする。**同じ月に複数のマイルストーンが重なっていても、配列内で最初に見つかった1件しか描画されない**（例えば早期登録と後期登録が同月にまたがるケースで後者が消える。7章）。

帯のテキスト:
- 開催帯: `開催 | {society}`
- マイルストーン帯: `{短縮ラベル} | {society}`。短縮ラベルは`"演題募集"→"演題"`、`"参加登録"→"登録"`のみ変換され、それ以外のラベル文字列（`"事前参加登録"`等）は**そのままフルテキストで表示**される（長い場合は末尾を省略記号で切る）。

帯のリンク先: `primaryUrl`（無ければ`sources[0].url`）。安全でないURL（`javascript:`等やパース不能なもの）は空扱いになりリンク化されない。

帯のtitle属性（ホバー時のツールチップ）:
- 開催帯: `{eventName} / {開催日レンジのテキスト}`
- マイルストーン帯: `{eventName} / {マイルストーンのラベル}{ / noteがあれば note}`

### 3.7 週またぎ（行またぎ）の分割描画

- 帯の期間がグリッド上で複数週（複数行）にまたがる場合、行ごとに分割して複数の帯要素として描画する（各行の左右範囲にクリップ）。
- 分割後の2本目以降（継続部分）は「継続扱い」（`is-continuation`、パディングがやや狭い見た目）になり、テキストは:
  - 開催帯の継続 → その学会名（`society`）のみを再掲
  - マイルストーン帯の継続 → **空文字（無地の帯）**。マイルストーンが複数週にまたがっても2週目以降はラベルが一切表示されない（8章）。

### 3.8 重なり合う帯のレーン割当

同じ月のグリッド内で、複数の学会の帯が同じ週・同じ列にかぶる場合、縦方向に段組み（レーン）して重なりを避ける。規則:

- 行ごとに独立して計算する。
- 同じ行・同じ開始列の帯同士は「開催帯を先に処理」「開催帯同士/マイルストーン帯同士ならより長い期間の帯を先に処理」という順で並べ替えてから割り当てる。
- 各帯について、既存レーンの中で「そのレーンの直近の帯が自分の開始列より前に終わっている」空きレーンがあればそこに乗せ、無ければ新しいレーンを追加する（一般的な区間スケジューリングの貪欲法）。
- ある週で使われたレーン数の最大値に応じて、その週の行の高さが伸びる（レーンが多いほど背の高いマス）。

### 3.9 何もない月の表示

- その月に該当する開催・マイルストーンが1件も無くても、グリッド自体は通常通り描画される（日付マスと曜日見出しのみで、色付き帯が一切乗らない状態）。エラーやプレースホルダー文言は出ない。
- 「表示できる日程データがありません。」という文言が出るのは、**年度の月一覧自体が0件のとき**（`period`が不正な場合など）に限られる、極めて例外的なケース。

### 3.10 上部の凡例・募集期間サマリー（再掲・詳細）

- 凡例は静的な2チップのみ（3.3章参照）。
- 募集期間サマリーは、**現在表示中の月に関係なく、データ内の全学会**を対象に、可視マイルストーン（開始日・終了日が両方揃っているもの限定）を`"{eventName}: {ラベル} {期間} / {ラベル2} {期間2}"`の形で1行ずつ列挙する。該当が1件も無ければ固定の案内文に差し替わる。

## 4. リストビューの挙動

### 4.1 並び順とグルーピング

並び替えキー（`sortValue`）は `sortDate || startDate || (displayMonthからの年月フォールバック)` の優先順で決まる1つの日付文字列。

グループ分けと並び順の規則:

1. **`status === "past"` でない学会が、`status === "past"` の学会より必ず先に表示される。** 開催日の先後は一切関係ない（未来の確定学会は、直近で終わったばかりの学会よりも常に上に来る）。
2. 非`past`グループ内は`sortValue`の**昇順**（開催が早い順）。
3. `past`グループ内は`sortValue`の**降順**（終了が新しい順）。
4. グループ見出しのラベルは、非`past`は`sortValue`から取り出した年月（例:「2026年7月」）、`past`は一律「終了した学会」という単一グループにまとめられる。
5. **リストビューは`period`（年度範囲）でのフィルタを一切行わない。** 現行データには年度範囲（2026-04〜2027-03）より後の確定情報（2027年9月・2028年3月・2028年11月・2029年9月開催のもの）が含まれており、これらは**学会一覧タブには表示されるが、学会カレンダータブの月グリッドには絶対に出てこない**（月一覧が年度内にしか生成されないため）。この非対称性は現行の意図的な仕様であり、再実装でも踏襲する前提で明記しておく。

### 4.2 各カードの表示項目

各カードは1学会＝1枚。上から:

1. サムネイル画像リンク（クリックで公式サイトを開く。画像が無い/読み込み失敗時は`society`名を中央配置したフォールバック表示に切り替わる）
2. バッジ行（該当するものだけ。順序は「地域チップ→未公表チップ→終了チップ」）
3. タイトル（`eventName`。公式サイトへのリンク。2行で省略）
4. 「開催日時」= `formatDateRange`の結果（4.2.1参照）
5. 「開催場所」= `venue`（無ければ「会場未公表」）＋ `city`があれば` / city`を続ける
6. 「テーマ」= `theme`。**空/未設定なら行ごと非表示**
7. マイルストーン一覧（`milestones`が1件以上あるときのみ）— 各マイルストーンにつき「ラベル（太字）＋期間テキスト」。**除外フィルタなし＝「早期参加登録」も含め全件表示**（カレンダー/サマリーとの非対称、1.3章参照）。期間テキストは開始日・終了日が両方あれば期間表記、無ければ「日程調整中」
8. `note`（学会単位の補足）— **空/未設定なら非表示**

#### 4.2.1 「開催日時」の表記規則（`formatDateRange`）

- 開始日・終了日どちらか一方でも無ければ「会期未公表」。
- 開始日＝終了日（1日開催）なら `YYYY年M月D日(曜日)` のみ。
- 同一年・同一月内の複数日開催なら `YYYY年M月D日(曜日)〜D日(曜日)`。
- 月または年をまたぐ開催なら `開始の完全表記〜終了の完全表記`。

### 4.3 `status` ごとの表現（カード単位）

- `past`: カード全体に減光（`filter: saturate(0.82)`相当の演出）＋枠線を控えめな色に変更＋「終了」バッジ。
- `pending`: 枠線をアクセントカラー寄りに変更＋「未公表」バッジ。減光は無い。
- `confirmed`（または未指定）: 通常表示、バッジ無し。

### 4.4 `leadLabel`/`lead`・`sources`について（重要な明記）

- `leadLabel`と`lead`（会長/年会長の肩書と氏名）は、**データスキーマには存在するが現行の描画コードのどこからも参照されておらず、画面には一切表示されない**。
- `sources`配列も同様に、**リンク一覧としては描画されない**。使われるのは`sources[0].url`のみで、それも`primaryUrl`が空のときのフォールバックとしてのみ（画像リンク・タイトルリンク・カレンダー帯リンクの3箇所で共通利用）。2件目以降の`sources`エントリ（例:「一般演題登録」「参加登録」個別ページへのリンクなど）は現状どこにも表示されない。
- 再実装時にこれらを表示するかどうかは仕様上の新規判断が必要（現状維持＝非表示のままにするのが「忠実な再現」であり、表示する場合は仕様追加として扱うべき）。

## 5. 状態→スタイルのマッピング表

### 5.1 `status`

| status | カレンダービュー | リストビュー |
|---|---|---|
| `confirmed` / 未指定 | 通常の色付き帯 | 通常表示 |
| `past` | 開催帯は通常通り描画される（過去/未来で色や形は変えない） | カード全体を減光＋「終了」バッジ＋4.1章の並び順で末尾グループへ |
| `pending` | 該当データが無ければ影響なし（開催日未定なら期間重複判定自体が成立せず帯は出ない） | カードに「未公表」バッジ＋ページ上部に専用ノーティス（2.1章） |

### 5.2 マイルストーン `category`

| category | 意味 | 見た目のクラス |
|---|---|---|
| `abstract` | 演題募集 | `is-abstract` |
| `registration` | 参加登録 | `is-registration` |
| `deadline` | （現行データ未使用）締切系 | `is-deadline` |
| その他/未設定 | 汎用 | `is-info` |

ただしこれらのクラスは**あくまで意味付けのラベルであり、実際に画面に出る色ではない**（5.4章参照）。

### 5.3 `scope`

| scope | 表現 |
|---|---|
| `local` | カードに固定文言「北海道/札幌」チップを追加（`city`の値に関わらず常にこの文言。8章で要注意点として言及） |
| `national` / 未指定 | チップ無し |

### 5.4 重要な注記: カレンダー帯の実際の色は「カテゴリ」ではなく「学会ごとのハッシュ色」

カレンダー帯（開催/マイルストーン共通）の背景色・枠線色・文字色は、`category`によるクラス（`is-event`/`is-abstract`/`is-registration`など）の既定色を**インラインスタイルで上書き**し、`id`（無ければ`society`）の文字列ハッシュから機械的に算出した色相（0〜360度）を使う。つまり:

- 同じ学会は月をまたいでも常に同じ色相の帯になる（識別しやすくする意図と推測される）。
- 開催帯（`meeting`）はマイルストーン帯より彩度・コントラストがやや高く設定される。
- **カレンダー上部の凡例（「開催」「演題募集」の2チップ）が使っている色（クラス既定色）と、実際に画面に並ぶ帯の色は一致しない。** 凡例は「意味のカテゴリ分け」を示すのみで、実際の帯色は学会ごとの識別色になっている。この不一致は現行実装の仕様上の癖であり、再実装時に凡例の意味を再設計するか、帯の配色方式自体を見直すか、判断が必要（8章）。

## 6. アクセシビリティ挙動

- タブ切り替え: `role="tablist"`/`role="tab"`/`role="tabpanel"`、`aria-selected`、`aria-controls`、ロービング`tabindex`（アクティブのみ`0`）、矢印キー左右でのタブ間移動（3.2章参照）。
- 「今日」セル: `aria-current="date"` と `aria-label="{月}月{日}日 今日"` を付与。
- ライブリージョン: カレンダー本体コンテナ（`meeting-calendar`）と一覧セクション（`meeting-groups`）はともに`aria-live="polite"`。月送りナビ操作や初回データ反映時にスクリーンリーダーへ変更が通知される想定。
- 画像リンク: `aria-label="{eventName}の公式サイトを開く"` を画像カードのアンカーに付与。
- 外部リンク全般: `target="_blank"` + `rel="noreferrer noopener"` を自動付与（安全なURLと判定されたものにのみ）。
- キーボード操作はタブ切り替えの左右矢印のみで、カレンダーの月送り自体にショートカットキーは無い（ボタンをTab移動して通常のEnter/Spaceで操作する想定）。

## 7. エッジケース

| ケース | 現行の挙動 |
|---|---|
| `endDate`が無い（`startDate`のみ、または両方無し） | `formatDateRange`は「会期未公表」。カレンダー上にも開催帯は出ない（重複判定に両方の日付が必須） |
| マイルストーンが`startDate`のみ/`endDate`のみ | 存在する方の日付を両端にコピーして「1日だけの期間」として扱う。カレンダー・サマリーでは単日の帯/テキストとして表示され、「その日から始まって終了日未定」というニュアンスは表現されない。リストビューでも同様に単日表記になり、実質は`note`の自由文（「締切は未公表」等）に説明を委ねている |
| マイルストーンが`startDate`・`endDate`ともに無い（`note`のみ） | カレンダー・募集期間サマリーには**一切表示されない**（重複判定・期間整形の両方が日付必須のため）。リストビューでは「日程調整中」という専用テキストで表示される（唯一この状態が識別できる場所） |
| `imageUrl`が空文字 | 最初からフォールバック表示（`society`名を中央配置したプレースホルダー） |
| `imageUrl`はあるが読み込みエラー | `<img>`のerrorイベントで動的に画像を除去し、フォールバック表示に切り替える（空文字の場合と最終的に同じ見た目になる） |
| `sources`が複数件 | 4.4章の通り、`sources[0].url`のみが使われ、他は現状描画に一切関与しない |
| `displayMonth`のみで`startDate`/`sortDate`が無い（開催日完全未定のレコード） | 並び替え・グルーピング用の日付を`"{period.end年}-{displayMonthの2桁}-31"`として合成する。**`period.end`の年（年度末側の年、例: FY2026なら2027）を無条件に使うため、年度前半（4〜12月）を指す`displayMonth`では実際より1年進んだ年でグルーピングされる潜在バグがある**（例: `displayMonth=5`＝本来2026年5月のつもりでも「2027年5月」グループに入ってしまう）。現行データには該当レコードが無いため顕在化していないが、`pending`かつ日付完全未定のレコードを追加すると発生しうる |
| 同月内で開催期間とマイルストーン期間が両方重なる | 開催帯のみ描画され、マイルストーン帯は同月では表示されない（3.6章） |
| 同月内で複数マイルストーンが重なる | 配列内で最初に一致した1件のみ描画され、他は表示されない（3.6章） |
| ラベルが厳密に「早期参加登録」のマイルストーン | カレンダー帯・募集期間サマリーからは除外。リストビューのカード内では通常通り表示される（1.3章） |
| `period`範囲より後（または前）の日付を持つ`meetings`エントリ | カレンダーの月グリッドには出現しないが、リストビューには通常通り出現する（4.1章の非対称性） |
| `pending`学会が複数件ある | 上部の「未公表」ノーティスには最初の1件の`note`のみ表示される（他のpending学会のnoteは表示先が無い） |

## 8. 新実装への注記

### 8.1 SSR化に伴い不要になるもの

旧実装はクライアントサイドの`<script>`読み込みタイミング競合を吸収するため、`window.ANNUAL_MEETINGS_2026_DATA`が定義されるまで最大40回×100msのポーリングでリトライし、失敗時にのみエラーパネルを`meeting-groups`内に表示する仕組み（`loadMeetingData`/`attemptLoad`/`MEETING_DATA_RETRY_LIMIT`/`MEETING_DATA_RETRY_DELAY_MS`）を持っていた。新実装は`loadAnnualMeetingsData()`でサーバー側にてJSONを直接読み込みSSRで注入するため、この**遅延ロード・リトライ・読み込み中/エラー表示の分岐は不要**になる。あわせて、この読み込み状態パネル（`meeting-status-panel`）が学会一覧タブの中にしか存在せず、カレンダータブでは読み込み失敗時に何のフィードバックも出ない、という旧実装の欠落もSSR化によって自然に解消される。

### 8.2 引き継ぐべきでない/要判断な挙動（バグ・不自然な癖）

- **凡例と実際の帯色の不一致（5.4章）**: 凡例は「開催」「演題募集」の2種類の意味カテゴリを示すが、実際の帯色は学会ごとのハッシュ色で決まり、かつ「参加登録」チップが凡例に存在しない。そのまま複製すると誤解を招く設計を継承することになるため、再実装時に凡例の意味（カテゴリ別色 or 学会別識別色のどちらを主とするか）を再設計することを推奨する。
- **同月内でのマイルストーン取りこぼし（3.6章・7章）**: 開催期間とマイルストーン期間の同月重複、または複数マイルストーンの同月重複時に、片方が無条件に非表示になる。データが増えるほど発生しやすくなる制約であり、意図的な設計というよりは「1学会1月1帯」という描画モデルの単純化による副作用に見える。再実装では、同月に複数の帯を許容する（レーンをさらに使う）などの改善余地がある。
- **マイルストーン継続帯（週またぎ2週目以降）のラベル欠落（3.7章）**: マイルストーン帯が複数週にまたがると2週目以降は空欄の帯になり、何の帯か視覚的に分からなくなる。開催帯は学会名を再掲するのに対し非対称。
- **`displayMonth`フォールバックの年ズレ（7章）**: `period.end`の年を無条件に使うため、年度前半月で1年ずれる潜在バグ。現行データでは未顕在化だが、再実装時は年度の開始/終了のどちらの年を使うべきかを`displayMonth`の値に応じて正しく分岐させること。
- **`scope: "local"`の地域名ハードコード（5.3章）**: 「北海道/札幌」という文言が`scope`の値だけで決まり、`city`フィールドと無関係にハードコードされている。将来「北海道/札幌」以外のローカル学会を追加すると誤表示になる。再実装では`city`から動的に生成するか、地域名自体をデータフィールド化するべき。
- **`milestoneLabel`の`category`フォールバックの粗さ（1.3章）**: ラベル未設定時、`registration`以外は無条件に「演題募集」になる。`deadline`や`info`カテゴリを今後ラベル無しで使うと誤ラベルになる。
- **ラベル文字列完全一致による特別扱い（1.3章）**: 「早期参加登録」という文字列そのものへの一致で表示/非表示を切り替えている。表記ゆれ（全角/半角、末尾の言い回し違いなど）に弱く、データ側の言葉遣いを変えただけで意図せず表示状態が変わる。再実装ではマイルストーン側に明示的な可視性フラグ（例: `hiddenFromCalendar: boolean`）を持たせる方が堅牢。
- **`leadLabel`/`lead`・`sources`の未描画（4.4章）**: バグではないが、データに存在するのに画面に出ない項目がある状態を無自覚に引き継がないよう、再実装時に「表示する/しない」を意識的に決めること。
- **既存TypeScript型定義の不足**: `app/site-data.ts`の`AnnualMeeting`型には`scope`・`displayMonth`・`city`・`venue`・`theme`・`leadLabel`・`lead`・`sources`・`imageFit`が定義されておらず、実データ（`public/data/annual-meetings-2026.js`）と乖離している。再実装時はこの型を実データに合わせて拡張する必要があり、既存の型定義を仕様のソースとして信頼してはならない。

### 8.3 明確に「意図的な仕様」として踏襲すべき挙動

- カレンダービューは年度範囲（`period`）に厳密に閉じ、リストビューは範囲外の将来確定情報も表示する非対称設計（4.1章）。これは一覧をFY横断の「先の予定を見る場所」として使う設計意図と解釈できるため、バグ扱いせず踏襲を推奨する。
- 過去学会をリスト末尾にひとまとめにし、内部は新しい順（直近に終わったものが先頭）に並べる規則（4.1章）。
